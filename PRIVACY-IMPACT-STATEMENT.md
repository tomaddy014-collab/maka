# Māka — Privacy Impact Statement (for school review)

**Tool:** Māka, an AI-assisted marking and feedback tool for NZ teachers (Years 7–8, refreshed NZC)
**Operator:** [name + contact details]
**Date:** 12 June 2026
**Status:** Personal tool built by a teacher; offered to colleagues for classroom use

---

## 1. Purpose

Māka helps teachers mark student work against NZC-aligned rubrics, generate feedback and report comments in the teacher's own writing voice, and track student progress over time. Students can view their own results through a private, read-only learning page.

## 2. Personal information collected

| Data subject | Information | Source | Purpose |
|---|---|---|---|
| Students | Name, year level, gender (optional — used only for report pronouns) | Entered by the teacher | Class management, pronoun-correct comments |
| Students | Work samples (PDF/photo), marks, written feedback | Uploaded/generated by the teacher | Marking, progress tracking, reporting |
| Teachers | Email, display name, writing-style samples, Google Gemini API key | Provided at sign-up / in settings | Account access and tool features |

Not collected: student contact details, NSN numbers, health or attendance data, analytics, behavioural tracking, cookies for advertising.

## 3. Storage and security

- All data is stored in a managed **Supabase** project (PostgreSQL + file storage; SOC 2 Type II–certified infrastructure) administered by the operator.
- **Isolation:** database row-level security ensures each teacher can access only their own class data.
- **Student work files** are held in a private storage bucket, never publicly listable; files are served only via expiring signed links.
- **Student access** is via individual private codes (no student accounts or passwords). Codes use a high-entropy format to resist guessing.
- **Transport:** all traffic is HTTPS.

## 4. AI processing and model training

- Marking is performed by **Google Gemini API on the paid (billing-enabled) tier**.
- Under Google's Gemini API terms for the paid tier, **prompts and responses are not used to train or improve Google's models** and are retained only briefly for abuse monitoring. Reference: https://ai.google.dev/gemini-api/terms
- Each piece of work is processed once, transiently, to produce marks and feedback. Māka performs no model training of its own.
- The tool explicitly instructs all teachers to use paid-tier keys for student work; free-tier keys (whose terms permit training use) are warned against in the interface.

## 5. Disclosure

Personal information is disclosed to exactly two processors and to no one else:

1. **Supabase** — database and file hosting.
2. **Google (Gemini API)** — transient AI processing of submitted work for marking, under the paid-tier no-training terms above.

No information is sold, shared with advertisers, or used for any secondary purpose.

## 6. Access, correction, retention, deletion

- Teachers can view, edit, and delete student records, sessions, and files at any time within the tool.
- Teachers can delete their entire account and all associated data via Settings ("Delete my account and all data").
- Data is retained until deleted by the teacher. Schools may request deletion of any student's data via the operator contact above.
- Parents/whānau and students may direct access or correction requests to the classroom teacher or the operator (Privacy Act 2020, IPPs 6–7).

## 7. Identified risks and mitigations

| Risk | Mitigation |
|---|---|
| Unauthorised access to student work | Private bucket, expiring signed URLs, RLS isolation, high-entropy student codes |
| Student work used to train AI | Paid-tier Gemini only; in-app warnings against free-tier keys |
| Cross-teacher data exposure | Row-level security on all tables, scoped to the authenticated teacher |
| Operator access | Operator does not access content except for service maintenance; single named operator accountable |
| Data loss | Supabase managed backups; teachers can export results to CSV at any time |

## 8. Open items / honest limitations

- Māka is operated by an individual teacher, not a company; there is no dedicated security team. The external surface is small (two processors, no public APIs beyond code-gated student lookups), but schools should weigh this.
- Teachers' Gemini API keys are stored in the database to enable the tool's features; key storage hardening is on the roadmap.
- This statement should be reviewed against the school's own privacy policy and, if adopted school-wide, recorded in the school's PIA register.
